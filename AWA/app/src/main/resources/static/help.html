Android Webcam App

Available endpoints :

GET '/video'

MJPEG stream.

GET /features

Get available features. e.g.


{
    "resolutions": ["640x480","1280x720","1920x1080","3840x2160","4000x3000"],
    "manual_focus": true,
    "exposure_lower": -20,
    "exposure_upper": 20,
    "stream_protocol": "MJPEG"
}

resolutions is read from the camera itself, smallest first, so the last entry is the sensor's own frame (here 4000x3000, 12 MP). resolution_str takes one of those keys, or "native" for the largest. In MJPEG mode the list is no longer capped at the camcorder profile, but it stops at 13 MP because the phone holds two or three NV21 copies of every frame; in RTSP mode it is still capped, because the hardware encoder decides.

Get /settings

Get current settings. e.g.


{
    "focus_mode": 0,
    "focus_distance": 0.0,
    "exposure_index": 0,
    "zoom": 1.0,
    "stream_quality": 80,
    "flip": false,
    "resolution_str": "2304x1728",
    "resolution_requested": "3840x2160",
    "camera": "back",
}

resolution_str is what the camera is really delivering; resolution_requested is what was asked for. They differ when the camera refuses a size - a sensor size that cannot run next to a preview, for instance - and CameraX picks the closest one it will accept.

Get /control

Get current settings. e.g.


{
    "focus_mode": 0,
    "focus_distance": 0.0,
    "exposure_index": 0,
    "zoom": 1.0,
    "stream_quality": 80,
    "flip": false,
    "resolution_str": "1280x720"
    "camera": "back",
}

POST /settings

Set settings endpoint. Post a JSON object with the desired settings to update multiple states at once. e.g. 


{
    "focus_mode": 0,
    "focus_distance": 0.0,
    "exposure_index": 0,
    "zoom": 1.0,
    "stream_quality": 80,
    "flip": false,
    "resolution_str": "1280x720"
    "camera": "back",
}

Get / Post background removal

The background is removed on the phone, before the frame is encoded, so anything reading the MJPEG stream already receives the composited picture. Three engines are available: a chroma key (needs a green or blue screen), a person segmentation model (works with any background) and a background plate (shoot the empty room once; the camera must stay put). background_mode picks one. Send any of these fields to POST /settings, or pass them as query parameters to GET /control. They are also returned by GET /settings. 


{
    "camera": "back",
    "chroma_key": true,
    "background_mode": "auto",
    "chroma_key_color": "#00FF00",
    "chroma_key_similarity": 0.28,
    "chroma_key_smoothness": 0.12,
    "chroma_key_spill": 0.45,
    "segmentation_threshold": 0.5,
    "segmentation_feather": 0.2,
    "segmentation_smoothing": 0.35,
    "plate_sensitivity": 0.5,
    "plate_feather": 0.35,
    "plate_smoothing": 0.4,
    "chroma_key_background_color": "#101018",
    "chroma_key_gpu": true
}

background_mode is "auto" (default), "chroma", "person" or "plate". auto decides from the frame border: a coloured screen filling the border selects the keyer, anything else selects the segmentation model. The decision is re-checked roughly every two seconds and only changes after two agreeing probes, so a green object entering the shot cannot flip the stream back and forth.

Chroma key: chroma_key_similarity (0..1) is how much colour difference still counts as screen. chroma_key_smoothness (0..0.6) is the width of the soft edge, which is what keeps hair and shoulders from looking cut out. chroma_key_spill (0..1) removes the green cast the screen bounces onto the subject.

Person segmentation: segmentation_threshold (0.1..0.9) moves the cut in or out, segmentation_feather (0.01..0.5) sets how soft the edge is, and segmentation_smoothing (0..0.9) averages consecutive masks - more smoothing is less flicker for a little more lag. The mask trails the frame by one or two frames by design; waiting for it inside the capture loop would halve the frame rate.

Background plate: plate_capture=true (GET /control or POST /settings) shoots a new plate from the next frames and switches background_mode to "plate" - make sure the scene is empty for a moment. plate_sensitivity (0.1..0.9) trades leftovers of the room against keeping clothes and hair that match the wall, plate_feather (0..1.5) is the soft edge and plate_smoothing (0..0.9) averages consecutive mattes. plate_ready in GET /settings tells you whether a plate exists for the current frame size; a change of resolution or camera drops it.

chroma_key_gpu selects the Vulkan compute keyer for the chroma path; false forces the CPU implementation. Person segmentation always composites on the CPU. GET /settings reports what is really running as background_engine (for example "Vulkan · Adreno (TM) 640", "CPU" or "ML Kit · person"), because a device without a usable driver - or without a working model - falls back silently.

The key colour is re-sampled from the border of the frame a few times per second, so an unevenly lit screen still keys out; chroma_key_color is the starting point and the fallback. A picture as replacement background can only be picked on the phone.
